# ZD-MAST benchmark

`ZD-MAST` is the clean public-code candidate for **ZD-MAST: a
two-site, two-platform MALDI-TOF mass spectra and antimicrobial susceptibility
benchmark**.

This repository contains data validation, feature reconstruction, frozen cohort
contracts and exact rerun entry points. It does not contain hospital exports,
original identifiers, exact private timestamps, patient-level private
predictions, vendor-native files or third-party benchmark data.

## Data products

The companion deposition contains 17 checksum-verified archives:

- 64,611 de-identified sample rows;
- 79,713 spectra/open peak tables, including 70,336 from ZD-MAST-A and 9,377
  from ZD-MAST-B;
- sample- and spectrum-level `intensity6000` and `peak_presence6000` matrices;
- 1,117,585 de-identified AST measurement rows;
- 1,117,719 sample-organism-antimicrobial label rows linked to 62,434 released
  samples;
- the frozen historical ten-task layer with 59,978 unique sample-task labels.

The 16 scientific-data archive identities and SHA-256 values inherited from the
validated RC2 base are frozen in `manifests/`. The checksum of the code archive
that contains this repository is recorded only in the outer deposition manifest,
avoiding a circular self-checksum.

## Installation

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install '.[modeling,test]'
```

Python 3.11 is the frozen major/minor version. The exact analysis dependencies
are listed in `requirements-analysis.txt` and `environment.yml`.

## Validate the data release

After extracting the metadata and feature archives into one release root:

```bash
zd-mast validate-data ${ZD_MAST_PUBLIC_DATA_ROOT}
python scripts/validate_public_release.py \
  --release-root ${ZD_MAST_PUBLIC_DATA_ROOT}
```

## Rebuild features from open peak tables

```bash
zd-mast rebuild-features . ${ZD_MAST_PUBLIC_DATA_ROOT} \
  ZD-MAST-A output/rebuild_site_a --workers 16

zd-mast rebuild-features . ${ZD_MAST_PUBLIC_DATA_ROOT} \
  ZD-MAST-B output/rebuild_site_b --workers 16
```

## Exact analysis reruns

The commands below use public identifiers and frozen split files. They do not
use original hospital identifiers or exact private timestamps.

```bash
zd-mast reproduce-primary . ${ZD_MAST_PUBLIC_DATA_ROOT} output/primary

zd-mast reproduce-patient-episode . ${ZD_MAST_PUBLIC_DATA_ROOT} \
  output/primary/zd_mast_primary_protocol_b_reproduced_metrics_v1.0.0.csv \
  output/patient_episode

zd-mast reproduce-m100-agreement . ${ZD_MAST_PUBLIC_DATA_ROOT} output/m100

zd-mast reproduce-cross-platform . ${ZD_MAST_PUBLIC_DATA_ROOT} \
  output/cross_platform
```

The primary temporal analysis, patient/episode sensitivity, M100 agreement and
ZD-MAST-A to ZD-MAST-B source-only stress test have frozen expected outputs in
`results/expected/`. Target-label pooling and adaptation analyses are not
described as independent external validation.

The latest review-facing analysis utilities also include performance-independent
task-universe auditing, calendar-year patient-purged temporal evaluation,
same-test training-history comparison, logistic-regression sensitivity,
same-cohort representation comparison and calibration/ECE post-processing.
These utilities do not change the historical ten-task panel and must not use
target-test labels for model or preprocessing selection.

The feature rebuild uses the explicit public `feature_row` contract. Site A
presence is derived from sparse peak-list-like exports. Site B presence uses the
frozen label-free dense-profile peak extraction rule; it is not generated by
thresholding all positive baseline intensities.

## Evidence boundaries

- The ten organism-antimicrobial pairs form a historical evaluation panel, not
  a data-driven prospective task selection.
- The March-June 2026 Site A evaluation is retrospective out-of-time.
- ZD-MAST-B source-only testing is a cross-platform external stress test.
- Analyses that use ZD-MAST-B labels for training are joint-development or
  adaptation simulations.
- Silent-run records are operational evidence and are not distributed at the
  private prediction-row level.

See `docs/reproducibility.md`, `docs/data_access.md` and
`docs/data_governance.md` before using the data.
